## 1. 決定：コーパスの目的は「最適な方式を自律選択する根拠」を作ること

**HyBIT は、利用者が個々の前処理・反復法を細かく指定しなくても、行列と右辺、要求精度、メモリ上限、再利用予定、実行中の収束状態に基づいて、実行可能な方法を選び、必要なら切り替え、認証済みの解を効率よく返す Autonomous Hybrid Sparse Solver を目指す。**

コーパスの存在意義は、ある特定の前処理を速くすることでも、単に多数の行列を解くことでもない。**同一条件で複数方式を比較し、各方式の得意・不得意と費用対効果を、未知の問題にも通用する選択規則として抽出・検証すること**にある。

局所 Cholesky、Two-Level、ネイティブ Multilevel AMG、Jacobi、ILU(0)、ABTM は競合する個別目標ではなく、自律ソルバの選択肢・観測手段・計算基盤である。すべてを常に実行する設計でも、単一方式を常に勝者とする設計でもない。

既存の `docs/DEVELOPMENT_PLAN_0.10.0.md` にある「数値的に正しい収束救済を最優先する」という要求は維持する。自律選択器は、その目的を達成するための制御機構であり、救済を犠牲にして反復回数だけを最小化してはならない。

## 2. 数学的な適用範囲と候補方式

最初に行列クラスの契約を確定する。**対角が正、あるいは行列が対称というだけで SPD と推定しない**。ユーザー・FEM ホストが宣言した数学的契約と、その独立した検査・出典に従う。

| 行列クラス | 利用可能な候補 | 方針・制約 |
| --- | --- | --- |
| 宣言・検証された SPD | Jacobi-PCG、既存 Hybrid 局所 Cholesky、代数的 Two-Level、研究用 native Multilevel V-cycle | 固定された SPD 互換前処理で PCG。Multilevel は現時点で実験実装であり本番 `Auto` 未統合。 |
| GeneralSquare | FGMRES + Jacobi / ILU(0) 等の明示された既存候補 | PCG の SPD 前提を流用しない。右前処理・再始動長を含む別の比較コーパスで評価。 |
| SymmetricIndefinite、矩形 | 現在の高水準 API での未実装クラス | 使える方式がない場合は明示的に unsupported とし、SPD-PCG に黙って振り分けない。 |

現段階では「解法群全体の自動化」を一度に完成させず、**SPD 前処理選択を最初の C1-G5 対象**とする。GeneralSquare の ILU(0) と ILU(0)-ABTM 選択は別のデータ集合・ゲートとする。

## 3. 入力と低コスト特徴量

実行時の選択に使える情報と、コーパスの評価にだけ使える情報を明確に分離する。

**実行時に利用可能な候補特徴量**：

- **要求・資源**：行列クラス、相対/絶対残差許容値、最大反復回数、局所因子/階層メモリ上限、使用スレッド・MPI 構成、同一係数行列での想定 RHS 数。
- **行列の疎構造**：DOF、NNZ、行次数分布、連結成分、局所密度、強結合グラフ、ブロック/構造場情報がホストから明示提供される場合のメタデータ。
- **軽量な数値指標**：対角スケール、対角と非対角の相対強度、低コストプローブで観測した進捗、必要に応じて正当性を伴う限定的なスペクトル診断。
- **RHS・実行状態**：ノルム、分布と局在性、初期残差、短い PCG プローブでの反復当たり残差減少率、停滞・Breakdown、準備済み前処理の有無。

特徴量抽出・ABTM 化・グラフ投影・短いプローブは**無料ではない**。その時間と追加メモリを選択方式の総コストへ計上する。後からしか分からない真の反復回数や最速方式のラベルを、選択時に利用可能な特徴量として扱わない（情報漏洩の禁止）。

**コーパスの教師・診断にだけ使う情報**：製造解 `x_ref`、実測された全候補の最終反復数・時間・メモリ、前進誤差、各候補の成否、oracle の最適方式。これらは通常の未知問題では選択前に取得できない。

## 4. 選択で最小化するものと数値的制約

単なる反復回数ではなく、実際の time-to-solution を評価する。係数行列が固定された場合の一例は：

\[
T_{\mathrm{total}} = T_{\mathrm{feature}} + T_{\mathrm{selection}} + T_{\mathrm{analysis}} + T_{\mathrm{setup}} + \sum_{k=1}^{N_{\mathrm{RHS}}}T_{\mathrm{solve},k} + T_{\mathrm{certification}} + T_{\mathrm{switch}}
\]

ここで `T_switch` は切替え時の追加前処理、残差再計算、PCG 再始動等の費用を含む。構築済み階層・因子を再利用するときは、準備コストを RHS ごとに二重計上しない。単発 solve と prepared multi-RHS は別の最適化問題として扱う。

**最適化より優先する制約**：

1. 数学的な行列クラスと前処理の適合性。
2. 元の係数行列・RHS による真残差認証（見かけの再帰残差だけで `Converged` としない）。
3. 最大反復回数、係数行列メモリ、局所因子・AMG 階層・一時バッファ・ピークRSSの資源上限。
4. Breakdown、MaxIterations、誤った収束判定、準備失敗、収束退行を隠さないこと。
5. 解の前進誤差は真残差のみでは一般に保証できないことを明示し、悪条件性・低エネルギーモードを監査すること。

必要な解精度の情報がない場合、残差許容値を前進誤差の保証に読み替えてはならない。利用者に見せるステータスと精度リスクの表示は分離する。

## 5. 静的選択と動的切替えを分離する

### 静的選択（solve/prepare 開始前）

行列構造・要求精度・予算・再利用数から、軽い Jacobi、局所補正 Hybrid、Two-Level、Multilevel のうち数学的・資源的に実行可能な候補を選択する。未知の領域では**安全側の既知ベースライン**を優先する。予測された最適候補の理由と予測された資源費を記録する。

### 動的選択（solve の観測・改善）

最初の選択が不適切なときは、反復進捗と独立真残差を観測して、**切替えの期待便益が追加費用を上回る場合にのみ**再構築・昇格する。同じ固定前処理なら PCG 再帰を保持できるが、前処理が変更された場合には元の `x` から残差を再計算し、**残りの共通反復予算の範囲で PCG を再始動**する。変更中に計算された進捗を古い前処理のまま継続してはならない。

動的試行は実装前に boundedness（最大切替え数、設定メモリ上限、打切り条件、再始動の計算契約）と比較対象を定義する。単一試行で速かった条件を本番既定のトリガーにしてはならない。

## 6. コーパスのデータ契約と oracle の定義

**一組の測定単位**は `(行列, RHS, 数学的クラス, 許容誤差, 反復予算, メモリ予算, 初期解, ハードウェア/スレッド, 再利用条件, 方式)` で固定する。同じ問題条件で各候補を走らせて初めて oracle を定義できる。

各行列ファミリー・RHS のレコードには少なくとも以下を保存する：

- 元 Matrix Market / CSR と RHS の SHA-256、出典、FEM 物理的 provenance、境界条件と自由度の所有、serial/MPI の区別、製造/物理 RHS の区別。
- 行列の数学的クラスの根拠と、数値データから確認できる範囲（SPD 未証明を SPD 認証済みに格上げしない）。
- プローブ開始前の特徴量・コスト、プローブ区間で観測したデータ、方式と設定、最大反復数・固定因子メモリ・階層メモリの上限。
- `Converged` / `MaxIterations` / `Breakdown` / `Unsupported` / `SetupError` 等の生の成績、元CSR真残差、可能なら独立参照解による前進誤差・Kahan残差。
- 行列入力・解析・準備・解法・切替え・認証・全プロセスの時間、ピークRSS、温/冷起動、同一行列での RHS 再利用数、ウォームアップと繰返し数。
- 実行コマンド、ソースHEAD、コンパイラ・依存バージョン、CPU/RAM、スレッド・ランク・親和性、全生ログと SHA-256。失敗例や遅かった候補も必ず保持する。

**oracle（事後的な最良方式）**は、同一条件で数値・メモリ等の制約を満たした候補のうち、*指定された利用形態での総コスト* が最小のものと定義する。制約を満たす候補が存在しなければ、`NO_FEASIBLE_ARM` として可視化する。収束しなかった方式を「高速だから勝者」としない。

**評価指標**：oracle に対する total-time regret（差分または比）、数値的な選択退行率、予算超過率、救済成功率、選択/切替えの追加コスト、メモリ増分、再利用数別の損益分岐点。収束ケースだけを抽出して平均速度を報告することは禁止する。

## 7. 汎化性能を測るための分割と段階的昇格

同じ行列の異なる RHS を学習用と検証用に振り分けるだけでは、**未知の行列に対する選択器の能力を証明できない**。最低限、行列ファミリー（生成手法・形状・物理場・離散化・条件数設定）単位で train / validation / held-out test を分離する。ハイパーパラメータ、閾値、評価に用いる特徴量は held-out 測定前に凍結する。

進め方：

1. **C1-G5A: 既存証拠の統一台帳** — Jacobi、Hybrid、Two-Level、Multilevel の成績を共通スキーマで整理。比較不可・欠測の欄は `NOT_RUN` 等とし、都合よく埋めない。
2. **C1-G5B: offline oracle / rule study** — 正確な適格候補と全費用に基づく oracle を計算。利用可能な入力特徴量だけで小さなルールを作る。
3. **C1-G5C: shadow selector** — 本番結果を変更せず、選ぶはずだった方式・理由・予測コスト・実測とのずれをログ化する。
4. **C1-G5D: held-out gate** — 新しい外部実FEM、物理的な RHS、異なる行列ファミリーで数値・メモリ・total-time regret を検証する。
5. **C1-G5E: 明示的 opt-in の自律切替え** — 同一条件の固定方式対照群を残し、PCG の前処理変更時再始動と資源上限を確認する。
6. **C1-G5F: 本番昇格判定** — 上記の独立したゲートを満たしたルールのみ `Auto` へ導入。無根拠な一律 AMG・ABTM・Hybrid 既定化を行わない。

外部 AMG（PETSc GAMG / hypre BoomerAMG）は比較すべき強い**外部ベースライン**だが、HyBIT 自体の実装を外部製品に依存させることは決定していない。ABTM はトポロジー抽出・強結合・粗空間等で効果を計測し、変換費用を払える場面だけ使う。

## 8. 今回までの証拠と注意点

### C1-G4：現行HEADでの多RHS回帰

- `5e30ec0` に確定した **72実行 / 36対応ペアのすべてが真残差認証つき `BOTH_CONVERGED`**。`RESCUE` も `REGRESSION` もゼロ。
- 構成FEM行列3種・粗格子構成3種・RHS4種（`ones`, `index_smooth`, `seeded_random`, `point_load`）。許容相対残差 `1e-10`、最大600反復、1スレッド。
- 全体の Two-Level 反復合計7,538に対し Multilevel 2,782。solver-only paired 時間比の中央値2.122、`ones` を除く27ペアでは1.921。ただし**各構成1試行**であり、統計的な速度優位・外部FEM・物理荷重・実行時選択の実証ではない。

### A10A：固定条件の精度別観測（ユーザー WSL2、2026-11-13）

対象：`island_shell / StrongGraph / JacobiSmoothed / SeededRandom`、同一行列・同一 `x_ref`、最大1200反復、プロセスごと1測定。ログ：`~/c1h11_evidence/c1g4_accuracy_azkEch`。

| 相対残差許容値 | Two-Level 反復 / 前進誤差 / total_wall_ms | Multilevel 反復 / 前進誤差 / total_wall_ms |
| --- | --- | --- |
| `1e-10` | 84 / `2.236e-5` / 70.800 | 18 / `2.049e-2` / 63.516 |
| `1e-12` | 108 / `1.071e-7` / 82.980 | 38 / `1.214e-7` / 75.296 |
| `1e-13` | 121 / `6.154e-8` / 90.490 | 40 / `1.063e-7` / 78.518 |

全6実行は `Converged` で、元CSRとKahan補償和による残差が整合した。Multilevel はこのケースの全許容値で反復数と実測 total wall が小さいが、`1e-10` では相対前進誤差が約2.05%であり、**真残差の小ささから解の正確さを直接保証できない**。`1e-12` にすると両方式でおおむね `1e-7` の前進誤差となった。これを理由に Multilevel 自体を排除せず、許容値・誤差リスク・総費用を**選択条件**として分析する。

誤差方向 Rayleigh 商は行列全体の最小固有値の証明ではない。Kahan残差の一致も絶対的な精度証明ではない。今回の前進誤差は製造解が存在するから測れたもので、未知の問題の自動選択入力ではない。

## 9. 決定事項と、まだ決定していない事項

**決定したこと**：コーパスは自律選択のための対照実験である。最初の対象は SPD 前処理候補群。数値的適格性・メモリ予算を絶対条件とし、最終的な判断対象は単独ソルバ速度ではなく総コストと救済・退行。基準群と生ログを保全し、まず offline、次に shadow、次に opt-in、最後に本番昇格という順序を守る。

**未決定**：どの特徴量・閾値が有効か、切替え判定の具体的数値、native Multilevel をいつ本番組込みするか、製造解のない現実の精度保証方式、MPI 分散下での hierarchy 再利用、未知ファミリーでの regret/安全性。これらは先にコーパスと対照実験で検証する。

**次の一手**：C1-G5A「既存結果からの**比較可能性を明記した統一コーパス台帳**」を作る。既存の `hybit::solve`／Rust/C ABI／本番 `Auto` の既定値は変更しない。

## 10. 追加設計決定（2026-11-14）：モデルの配置と配布

**標準モデルはRustライブラリ内蔵、外部モデルは任意、学習用の全コーパスはライブラリ外で管理する。** 外部モデルは利用側が明示的にロードする。推論・安全制御は`hybit-auto`内で行い、本番`hybit::solve`はPython・シェル・CSV/JSONを読み込まない。 未認証の標準モデルは棄権し、外部研究用モデルの診断スコアが数値安全条件や本番ルーティングを解除することはない。 実装・モデルV1契約・昇格条件は[C1-G5Dモデル配置方針](C1G5D_SELECTION_MODEL_POLICY.md)に記録。
