### Risk analysis / why the fixes matter

- **False convergence:** A recursive Krylov residual is only the residual of the recurrence in floating-point arithmetic, not a proof that original `b - A*x` satisfies the caller's tolerance. Drift matters especially on ill-conditioned and long-restart problems. This patch checks original CSR at the public high-level boundary; independent residual alone still does not prove forward accuracy.
- **Finite arithmetic:** Ordinary sum-of-squares overflows for finite `1e200` RHS and underflows for finite `1e-200` RHS. The former once triggered `Inf <= Inf` success in low-level PCG; the latter can produce a zero recursive residual. Low-level overflow now fails explicitly; high-level scaled certification detects false success after underflow. A future scaled Krylov reduction should be measured independently.
- **Diagnostics:** Calling a numerical breakdown “not converged” forces C/C++/Fortran consumers to treat bad arithmetic like an insufficient iteration cap. Correct error codes are important to meaningful automated FEM decisions.
- **Validation provenance:** The repository contains substantial Windows native MPI historical measurements; this Linux clone cannot rerun or certify those against the current patch. The native release gates remain required even when all default-feature Linux tests pass.

## Changes and numerical contracts

1. `hybit_krylov::pcg` still exposes an inexpensive recurrence-level `KrylovOutcome`; it is not redefined as a true-residual result. The high-level API adds independent certification against original CSR coefficients with a scaled overflow/underflow-resistant final norm, not a new solver algorithm.
2. The high-level final check requires one additional CSR SpMV, an `O(n)` temporary vector and a norm reduction per solve. The additional time is included in `SolveReport.solve_seconds`, not misattributed to `restart_seconds`. No end-to-end speedup is asserted.
3. A recursive `Converged` that fails original-system verification is classified as numerical `Breakdown`. `MaxIterations` is never silently promoted. Extremely large/non-finite inputs are rejected safely, not claimed to be solvable without scaling.
4. Existing `hybit::solve`, prepared solve-many, CSR32, the C report layout, FFI function signatures and solver/backend defaults remain unchanged. No MPI transport, rank policy, ABTM numeric backend or experimental SPD classification is promoted.
5. A small true residual **is not a forward-error or SPD certificate**. The documented `cant` example, with a small residual but poor manufactured-solution accuracy, remains a known limitation.

## Recommended release-quality numerical test matrix

| Family | Required independent oracle | Gate |
| --- | --- | --- |
| Diagonal/Poisson SPD, zero RHS, initial exact solution | Explicit original-CSR `b-Ax` and known solution | Correct status, no false iteration, exact/tight tolerance, serial/Rayon/prepared parity. |
| Ill-scaled SPD, nearly singular SPD, `1e-200` and `1e200` vectors | Stable reference norm, high-precision or independently scaled solver | No `NaN`/`Inf` success, no false convergence; distinguish a safe rejection from numerical capability. |
| Explicitly symmetric-indefinite and nonsymmetric examples | Independently characterized eigenvalue/solver class | No silent PCG/Cholesky routing on incompatible classes; FGMRES route tested under restarts and ILU fallback. |
| Real FEM `L-angle`, `thermal1`, `boneS01`, `cant` | Original CSR residual **and** manufactured/independent forward error where available | Accuracy, failure classification, time-to-solution and memory; residual-only PASS is insufficient for `cant`. |
| Repeated RHS, structure-preserving value changes, constraint/field changes | Cold-prepare solve and full independent solve | Cache reuse only for matching structure/values, deterministic invalidation, no stale factor/Halo. |
| MPI 1/2/4/8 ranks, varying partition/topology | Serial original-CSR result and rank-wide residual | No missing ghosts/deadlocks, rank-max stage timing, controlled affinity, peak RSS and repeated-launch dispersion. |

Do not turn performance into a single-number gate: record serial CSR, preparation, factorization, reuses, Krylov, communication, verification, maximum per-rank wall time and peak memory separately. For short MPI timings, compare multiple fresh processes under matched pinning and matrix/solver parameters; use held-out cases before changing production defaults.
